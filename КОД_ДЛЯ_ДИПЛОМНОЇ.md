### Реєстрація користувачів

Першим кроком була реалізація системи реєстрації. Потрібно було забезпечити безпеку паролів та унікальність email адрес.

```typescript
export const register = async (req: Request, res: Response, next: NextFunction) => {
  const { email, password, firstName, lastName, role } = req.body;
  
  // Перевірка чи користувач з таким email вже існує
  const existingUser = await prisma.user.findUnique({ where: { email } });
  if (existingUser) {
    throw new AppError('User with this email already exists', 400);
  }
  
  // Хешування пароля через bcrypt з salt rounds = 10
  // Це забезпечує безпеку паролів навіть якщо база даних буде скомпрометована
  const hashedPassword = await bcrypt.hash(password, 10);
  
  // Створення нового користувача в базі даних
  const user = await prisma.user.create({
    data: { 
      email, 
      password: hashedPassword, 
      firstName, 
      lastName, 
      role: role || 'STUDENT' // За замовчуванням студент
    },
    select: { id: true, email: true, firstName: true, lastName: true, role: true }
  });
  
  // Генерація JWT токенів для автоматичного входу після реєстрації
  const tokens = generateTokens(user);
  
  res.status(201).json({ success: true, data: { user, ...tokens } });
};
```

**Пояснення:** При реєстрації перевіряється унікальність email, пароль хешується через bcrypt, після чого створюється користувач та генеруються JWT токени для миттєвого входу в систему.

### Вхід користувача в систему

Далі було розроблено механізм входу з перевіркою облікових даних та генерацією токенів доступу.

```typescript
export const login = async (req: Request, res: Response, next: NextFunction) => {
  const { email, password } = req.body;
  
  // Пошук користувача за email
  const user = await prisma.user.findUnique({ where: { email } });
  if (!user || user.status !== 'ACTIVE') {
    throw new AppError('Invalid credentials', 401);
  }
  
  // Порівняння введеного пароля з хешем в базі даних
  const isPasswordValid = await bcrypt.compare(password, user.password);
  if (!isPasswordValid) {
    throw new AppError('Invalid credentials', 401);
  }
  
  // Оновлення часу останнього входу для аналітики
  await prisma.user.update({
    where: { id: user.id },
    data: { lastLoginAt: new Date() }
  });
  
  // Генерація пари токенів: access (короткоживучий) та refresh (довгоживучий)
  const tokens = generateTokens(user);
  
  res.status(200).json({ success: true, data: { user, ...tokens } });
};
```

**Пояснення:** Система перевіряє email та пароль, оновлює час останнього входу та видає токени доступу. Використовується bcrypt.compare для безпечного порівняння паролів без зберігання їх у відкритому вигляді.

### Middleware для перевірки аутентифікації

Після цього перейшли до створення middleware для захисту API endpoints, який перевіряє JWT токени на кожному захищеному запиті.

```typescript
export const authenticate = async (req: Request, _res: Response, next: NextFunction) => {
  // Отримання токена з заголовка Authorization
  const authHeader = req.headers.authorization;
  
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    throw new AppError('No token provided', 401);
  }
  
  const token = authHeader.split(' ')[1];
  
  // Верифікація токена та отримання даних користувача
  const decoded = verifyAccessToken(token);
  
  // Перевірка чи користувач все ще існує та активний
  // Це важливо якщо адмін видалив користувача після видачі токена
  const user = await prisma.user.findUnique({
    where: { id: decoded.id },
    select: { id: true, email: true, role: true, status: true }
  });
  
  if (!user || user.status !== 'ACTIVE') {
    throw new AppError('User account is not active', 401);
  }
  
  // Додавання інформації про користувача до об'єкта запиту
  // Тепер в контролерах можна використовувати req.user
  req.user = { ...decoded, role: user.role };
  next();
};
```

**Пояснення:** Middleware витягує токен з заголовка, перевіряє його валідність, перевіряє статус користувача в базі та додає інформацію про користувача до запиту для подальшого використання в контролерах.

### Генерація та валідація JWT токенів

Одночасно реалізовано систему генерації access та refresh токенів з різними термінами дії.

```typescript
// Генерація короткоживучого access токена (за замовчуванням 1 година)
export const generateAccessToken = (user: Partial<User>): string => {
  const payload: TokenPayload = {
    id: user.id!,
    email: user.email!,
    role: user.role!
  };
  
  return jwt.sign(payload, JWT_SECRET, { expiresIn: JWT_EXPIRES_IN });
};

// Генерація довгоживучого refresh токена (за замовчуванням 7 днів)
export const generateRefreshToken = (user: Partial<User>): string => {
  const payload: TokenPayload = {
    id: user.id!,
    email: user.email!,
    role: user.role!
  };
  
  return jwt.sign(payload, JWT_REFRESH_SECRET, { expiresIn: JWT_REFRESH_EXPIRES_IN });
};

// Зручна функція для генерації обох токенів одночасно
export const generateTokens = (user: Partial<User>) => {
  return {
    accessToken: generateAccessToken(user),
    refreshToken: generateRefreshToken(user)
  };
};
```

**Пояснення:** Використовуються два типи токенів: access токен для щоденних запитів (короткоживучий) та refresh токен для оновлення access токена без повторного входу (довгоживучий). Це підвищує безпеку системи.

## Розробка системи управління курсами

### Отримання списку курсів з кешуванням

Далі перейшли до проектування системи управління курсами. Для покращення продуктивності реалізовано кешування популярних запитів через Redis.

```typescript
export const getCourses = async (req: Request, res: Response, next: NextFunction) => {
  const { status, level, categoryId, search, page = 1, limit = 10 } = req.query;
  
  // Формування умов для фільтрації курсів
  const where: Prisma.CourseWhereInput = {};
  if (status) where.status = status as Prisma.EnumCourseStatusFilter<'Course'>;
  if (level) where.level = level as Prisma.EnumCourseLevelFilter<'Course'>;
  if (categoryId) where.categoryId = categoryId as string;
  
  // Пошук по назві або опису курсу
  if (search) {
    where.OR = [
      { title: { contains: search as string, mode: 'insensitive' } },
      { description: { contains: search as string, mode: 'insensitive' } }
    ];
  }
  
  // Створення ключа для кешу (тільки для опублікованих курсів без пошуку)
  const cacheKey = `courses:${status || 'all'}:${level || 'all'}:${categoryId || 'all'}:${page}:${limit}`;
  
  // Спробувати отримати з кешу
  const cachedResult = search ? null : await cache.get<{ courses: unknown[]; total: number }>(cacheKey);
  
  if (cachedResult) {
    // Повернути дані з кешу без запиту до бази
    return res.status(200).json({ 
      success: true, 
      data: { 
        courses: cachedResult.courses, 
        pagination: {
          total: cachedResult.total,
          page: Number(page),
          limit: Number(limit),
          pages: Math.ceil(cachedResult.total / Number(limit))
        }
      } 
    });
  }
  
  // Якщо немає в кеші - запит до бази даних
  const [courses, total] = await Promise.all([
    prisma.course.findMany({
      where,
      include: { 
        teacher: true, 
        category: true, 
        _count: { select: { enrollments: true, lessons: true } } 
      },
      skip: (Number(page) - 1) * Number(limit),
      take: Number(limit),
      orderBy: { createdAt: 'desc' }
    }),
    prisma.course.count({ where })
  ]);
  
  // Збереження результату в кеш на 5 хвилин
  if (!search) {
    await cache.set(cacheKey, { courses, total }, { ttl: 300 });
  }
  
  res.status(200).json({ success: true, data: { courses, pagination: {...} } });
};
```

**Пояснення:** Система спочатку перевіряє кеш Redis. Якщо дані є - повертає їх миттєво. Якщо ні - виконує запит до бази та зберігає результат в кеш на 5 хвилин. Це значно зменшує навантаження на базу даних при частому перегляді курсів.

### Створення нового курсу

Після цього реалізовано функціонал створення курсів з автоматичною генерацією URL-friendly slug.

```typescript
export const createCourse = async (req: Request, res: Response, next: NextFunction) => {
  if (!req.user) throw new AppError('User not authenticated', 401);
  
  const { title, description, level, categoryId, price, duration } = req.body;
  
  // Генерація slug з назви курсу для SEO-friendly URLs
  // Наприклад: "React для початківців" → "react-dlya-pochatkivciv"
  const slug = title
    .toLowerCase()
    .replace(/\s+/g, '-')
    .replace(/[^a-z0-9-]/g, '');
  
  // Створення курсу зі статусом DRAFT (чернетка)
  // Викладач може опублікувати його пізніше
  const course = await prisma.course.create({
    data: {
      title,
      slug,
      description,
      level: level || 'BEGINNER',
      categoryId: categoryId || null,
      price: price || 0,
      duration: duration || null,
      teacherId: req.user.id, // Автоматично призначається поточний користувач
      status: 'DRAFT'
    },
    include: { teacher: true, category: true }
  });
  
  // Очищення кешу курсів, щоб новий курс з'явився в списку
  await cache.delByPattern('courses:*');
  
  res.status(201).json({ success: true, data: course });
};
```

**Пояснення:** При створенні курсу автоматично генерується slug для красивих URL, курс створюється зі статусом DRAFT, а кеш курсів очищається для відображення змін.

## Реалізація системи записів на курси

### Запис студента на курс

Далі було розроблено механізм запису студентів на опубліковані курси з автоматичною перевіркою наявності запису.

```typescript
export const enrollInCourse = async (req: Request, res: Response, next: NextFunction) => {
  if (!req.user) throw new AppError('User not authenticated', 401);
  
  const { courseId } = req.body;
  
  // Перевірка чи студент вже записаний на цей курс
  const existingEnrollment = await prisma.enrollment.findUnique({
    where: { 
      userId_courseId: { 
        userId: req.user.id, 
        courseId 
      } 
    }
  });
  
  if (existingEnrollment) {
    throw new AppError('Already enrolled in this course', 400);
  }
  
  // Перевірка чи курс опублікований та доступний для запису
  const course = await prisma.course.findUnique({ where: { id: courseId } });
  if (!course || course.status !== 'PUBLISHED') {
    throw new AppError('Course not available for enrollment', 400);
  }
  
  // Створення запису з початковим прогресом 0%
  const enrollment = await prisma.enrollment.create({
    data: {
      userId: req.user.id,
      courseId,
      status: 'ACTIVE',
      progress: 0 // Початковий прогрес
    },
    include: { 
      course: { 
        include: { teacher: true, category: true } 
      } 
    }
  });
  
  res.status(201).json({ success: true, data: enrollment });
};
```

**Пояснення:** Система перевіряє чи студент вже записаний, чи курс опублікований, після чого створює запис з початковим прогресом 0%. Використовується унікальний індекс userId_courseId для запобігання дублікатів.

## Система подання завдань та автоматична перевірка

### Автоматична перевірка тестів

Однією з ключових особливостей системи є автоматична перевірка тестів з різними типами питань. Це було реалізовано наступним етапом.

```typescript
export const submitTest = async (req: Request, res: Response, next: NextFunction) => {
  const { assignmentId, answers, timeSpent } = req.body;
  
  // Отримання завдання з усіма питаннями та правильними відповідями
  const assignment = await prisma.assignment.findUnique({
    where: { id: assignmentId },
    include: { 
      questions: { include: { options: true } }, 
      course: true 
    }
  });
  
  if (!assignment || assignment.type !== 'TEST') {
    throw new AppError('Assignment not found or invalid type', 404);
  }
  
  // Перевірка чи студент записаний на курс
  const enrollment = await prisma.enrollment.findFirst({
    where: {
      userId: req.user!.id,
      courseId: assignment.course.id,
      status: 'ACTIVE'
    }
  });
  
  if (!enrollment) {
    throw new AppError('You are not enrolled in this course', 403);
  }
  
  // Автоматична перевірка відповідей та підрахунок балу
  let totalScore = 0;
  let maxPossibleScore = 0;
  
  for (const question of assignment.questions) {
    maxPossibleScore += question.points;
    const userAnswer = answers.find(a => a.questionId === question.id);
    
    // Перевірка залежно від типу питання
    if (question.type === 'SINGLE_CHOICE' || question.type === 'TRUE_FALSE') {
      // Одиночний вибір: перевіряємо чи вибрана правильна опція
      const correctOption = question.options.find(o => o.isCorrect);
      if (userAnswer?.selectedOptions?.[0] === correctOption?.id) {
        totalScore += question.points;
      }
    } else if (question.type === 'MULTIPLE_CHOICE') {
      // Множинний вибір: перевіряємо чи всі правильні опції вибрані
      const correctOptions = question.options
        .filter(o => o.isCorrect)
        .map(o => o.id)
        .sort();
      const userOptions = (userAnswer?.selectedOptions || []).sort();
      if (JSON.stringify(correctOptions) === JSON.stringify(userOptions)) {
        totalScore += question.points;
      }
    }
    // Для текстових відповідей (SHORT_ANSWER, LONG_ANSWER) потрібна ручна перевірка
  }
  
  // Створення подання з автоматично розрахованим балом
  const submission = await prisma.submission.create({
    data: {
      assignmentId,
      userId: req.user!.id,
      score: totalScore,
      maxScore: maxPossibleScore,
      status: 'GRADED', // Автоматично оцінено
      submittedAt: new Date()
    }
  });
  
  res.status(201).json({ success: true, data: submission });
};
```

**Пояснення:** Система автоматично перевіряє тести з одиночним та множинним вибором, обчислює бал та зберігає результат. Текстові відповіді потребують ручної перевірки викладачем.

## Реалізація реального часу через WebSocket

### Ініціалізація Socket.io сервера

Для реалізації чату в курсах використано WebSocket технологію через Socket.io. Це було додано пізніше для покращення комунікації між учасниками курсу.

```typescript
export const initializeSocket = (httpServer: HTTPServer) => {
  // Створення Socket.io сервера з налаштуванням CORS
  const io = new SocketIOServer(httpServer, {
    cors: { 
      origin: (origin, callback) => {
        // Дозволяємо тільки локальні підключення
        if (!origin || origin.startsWith('http://localhost:') || origin.startsWith('http://127.0.0.1:')) {
          return callback(null, true);
        }
        callback(new Error('Not allowed by CORS'));
      }, 
      credentials: true 
    }
  });
  
  // Middleware для аутентифікації WebSocket підключень
  io.use((socket: AuthenticatedSocket, next) => {
    const token = socket.handshake.auth.token;
    if (!token) return next(new Error('Authentication error'));
    
    // Перевірка токена та додавання інформації про користувача до socket
    const decoded = verifyAccessToken(token);
    socket.userId = decoded.id;
    socket.userRole = decoded.role;
    next();
  });
  
  // Обробка підключень
  io.on('connection', (socket: AuthenticatedSocket) => {
    // Кожен користувач автоматично приєднується до своєї персональної кімнати
    socket.join(`user:${socket.userId}`);
    
    // Приєднання до кімнати конкретного курсу для чату
    socket.on('join:course', (courseId: string) => {
      socket.join(`course:${courseId}`);
      logger.info(`User ${socket.userId} joined course ${courseId}`);
    });
    
    // Обробка відправки повідомлення в чат курсу
    socket.on('course:message:send', async (data: { courseId: string; content: string }) => {
      // Перевірка доступу: чи користувач записаний на курс або є викладачем
      const course = await prisma.course.findUnique({ 
        where: { id: data.courseId } 
      });
      const isEnrolled = await prisma.enrollment.findUnique({
        where: { 
          userId_courseId: { 
            userId: socket.userId!, 
            courseId: data.courseId 
          } 
        }
      });
      
      if (!course || (!isEnrolled && course.teacherId !== socket.userId)) {
        return socket.emit('error', { message: 'Access denied' });
      }
      
      // Збереження повідомлення в базі даних
      const message = await prisma.message.create({
        data: {
          content: data.content.trim(),
          senderId: socket.userId!,
          courseId: data.courseId,
          isRead: false
        }
      });
      
      // Відправка повідомлення всім користувачам в кімнаті курсу
      io.to(`course:${data.courseId}`).emit('course:message:received', message);
    });
  });
  
  return io;
};
```

**Пояснення:** WebSocket сервер забезпечує реальний час комунікації. Кожен користувач приєднується до кімнати курсу, повідомлення зберігаються в базі та транслюються всім учасникам курсу миттєво.

## Обробка помилок та валідація

### Глобальний обробник помилок

Для централізованої обробки помилок створено глобальний middleware. Це було важливо для забезпечення стабільності системи.

```typescript
export const errorHandler = async (
  err: Error | AppError,
  _req: Request,
  res: Response,
  _next: NextFunction
): Promise<void> => {
  let statusCode = 500;
  let message = 'Internal Server Error';
  
  // Спеціальна обробка помилок бази даних Prisma
  if (isPrismaConnectionError(err) || 
      err instanceof Prisma.PrismaClientKnownRequestError ||
      err instanceof Prisma.PrismaClientValidationError) {
    try {
      await handlePrismaError(err);
    } catch (prismaError) {
      // handlePrismaError може викинути AppError з правильним статус кодом
      if (prismaError instanceof AppError) {
        statusCode = prismaError.statusCode;
        message = prismaError.message;
      } else {
        statusCode = 503;
        message = 'Database service temporarily unavailable';
      }
    }
  } else if (err instanceof AppError) {
    // Обробка кастомних помилок додатку
    statusCode = err.statusCode;
    message = err.message;
  }
  
  // Логування помилок для моніторингу
  if (statusCode >= 500) {
    logger.error('Server Error:', { 
      message: err.message, 
      stack: err.stack,
      url: _req.url,
      method: _req.method
    });
  } else {
    logger.warn('Client Error:', { 
      message: err.message, 
      statusCode,
      url: _req.url
    });
  }
  
  // Відправка структурованої відповіді клієнту
  res.status(statusCode).json({
    success: false,
    error: { 
      message,
      // В режимі розробки додаємо stack trace для дебагу
      ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
    }
  });
};
```

**Пояснення:** Глобальний обробник перехоплює всі помилки, логує їх, обробляє помилки бази даних окремо та повертає структуровані відповіді клієнту. В режимі розробки додається stack trace для полегшення дебагу.

### API Service з автоматичним оновленням токенів

Для спрощення роботи з API створено Axios інстанс з інтерцепторами. Це значно спростило роботу з аутентифікацією на фронтенді.

```typescript
export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:5000/api',
  headers: { 'Content-Type': 'application/json' }
});

// Request interceptor: автоматичне додавання токена до кожного запиту
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Response interceptor: автоматичне оновлення токена при 401 помилці
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    // Якщо отримали 401 (Unauthorized) - спробувати оновити токен
    if (error.response?.status === 401 && !error.config._retry) {
      error.config._retry = true;
      
      try {
        const refreshToken = localStorage.getItem('refreshToken');
        const response = await axios.post(`${API_URL}/auth/refresh`, { refreshToken });
        
        // Збереження нового access токена
        localStorage.setItem('accessToken', response.data.data.accessToken);
        
        // Повтор запиту з новим токеном
        error.config.headers.Authorization = `Bearer ${response.data.data.accessToken}`;
        return api(error.config);
      } catch (refreshError) {
        // Якщо refresh не вдався - вихід з системи
        store.dispatch(logout());
        window.location.href = '/login';
        return Promise.reject(refreshError);
      }
    }
    
    return Promise.reject(error);
  }
);
```

**Пояснення:** Інтерцептори автоматично додають токен до запитів та оновлюють access токен через refresh токен при закінченні терміну дії, забезпечуючи безперервну роботу користувача без повторних входів.

### Система кешування через Redis

Для зменшення навантаження на базу даних реалізовано кешування через Redis з fallback на пам'ять. Це було додано для покращення швидкості відповіді системи.

```typescript
export const cache = {
  // Отримання значення з кешу
  async get<T>(key: string): Promise<T | null> {
    const redis = getRedisClient();
    
    // Якщо Redis доступний - використовуємо його
    if (redis) {
      try {
        const cached = await redis.get(REDIS_CACHE_PREFIX + key);
        if (cached) {
          logger.debug('Cache HIT for:', key);
          return JSON.parse(cached) as T;
        }
        logger.debug('Cache MISS for:', key);
        return null;
      } catch (error) {
        logger.error('Error getting from cache:', error);
        return null;
      }
    }
    
    // Fallback: якщо Redis недоступний, система працює без кешування
    return null;
  },
  
  // Збереження значення в кеш з TTL (time to live)
  async set<T>(key: string, value: T, options?: { ttl?: number }): Promise<void> {
    const redis = getRedisClient();
    if (!redis) return;
    
    try {
      const serializedValue = JSON.stringify(value);
      if (options?.ttl) {
        // Зберігаємо з терміном дії (наприклад, 5 хвилин)
        await redis.setEx(REDIS_CACHE_PREFIX + key, options.ttl, serializedValue);
      } else {
        // Зберігаємо без терміну дії
        await redis.set(REDIS_CACHE_PREFIX + key, serializedValue);
      }
      logger.debug('Cache SET for:', key);
    } catch (error) {
      logger.error('Error setting to cache:', error);
    }
  },
  
  // Видалення за патерном (наприклад, всі ключі що починаються з "courses:")
  async delByPattern(pattern: string): Promise<void> {
    const redis = getRedisClient();
    if (!redis) return;
    
    const keys = await redis.keys(REDIS_CACHE_PREFIX + pattern);
    if (keys.length > 0) {
      await redis.del(keys);
      logger.debug('Cache DEL by pattern:', pattern);
    }
  }
};
```

**Пояснення:** Система кешування використовує Redis для зберігання популярних запитів. Якщо Redis недоступний, система працює без кешування, що забезпечує відмовостійкість. TTL дозволяє автоматично очищати застарілі дані.

### Ініціалізація Prisma Client з retry логікою

Для надійності реалізовано автоматичне переподключення при втраті з'єднання. Це було важливо для забезпечення стабільності роботи системи.

```typescript
import { PrismaClient } from '@prisma/client';
import { logger } from '../utils/logger';

const prisma = new PrismaClient({
  log: process.env.NODE_ENV === 'development' 
    ? ['query', 'error', 'warn'] 
    : ['error']
});

// Функція підключення з повторними спробами
export const connectDatabase = async (maxRetries = 3, delay = 2000): Promise<void> => {
  for (let i = 0; i < maxRetries; i++) {
    try {
      await prisma.$connect();
      // Тестовий запит для перевірки з'єднання
      await prisma.$queryRaw`SELECT 1`;
      logger.info('✅ Database connected successfully');
      return;
    } catch (error) {
      logger.warn(`Database connection attempt ${i + 1}/${maxRetries} failed`);
      if (i < maxRetries - 1) {
        // Очікування перед наступною спробою
        await new Promise(resolve => setTimeout(resolve, delay));
      } else {
        throw error;
      }
    }
  }
};

// Graceful shutdown: коректне відключення від бази
export const disconnectDatabase = async (): Promise<void> => {
  await prisma.$disconnect();
  logger.info('Database disconnected');
};

export default prisma;
```

**Пояснення:** Система автоматично намагається підключитися до бази даних кілька разів з затримкою між спробами. Це забезпечує стабільну роботу навіть при тимчасових проблемах з мережею або базою даних.

### Запуск сервера з graceful shutdown

Сервер налаштований для коректного завершення роботи при отриманні сигналів SIGTERM/SIGINT. Це забезпечує коректне завершення всіх процесів.

```typescript
async function startServer() {
  try {
    // Підключення до бази даних (обов'язково)
    logger.info('🔌 Connecting to database...');
    await connectDatabase();
    
    // Підключення до Redis (опціонально)
    await connectRedis();
    
    // Створення HTTP сервера
    const httpServer = createServer(app);
    
    // Ініціалізація WebSocket для реального часу
    initializeSocket(httpServer);
    logger.info('✅ WebSocket server initialized');
    
    // Запуск сервера на localhost
    const HOST = process.env.HOST || 'localhost';
    const server = httpServer.listen(PORT, HOST, () => {
      logger.info(`🚀 Server running on http://${HOST}:${PORT}`);
      logger.info(`📖 API Docs: http://${HOST}:${PORT}/api-docs`);
      
      // Запуск моніторингу здоров'я бази даних
      startDatabaseHealthCheck();
    });
    
    // Graceful shutdown: коректне завершення при отриманні сигналу
    const gracefulShutdown = async (signal: string) => {
      isShuttingDown = true;
      logger.info(`${signal} received, shutting down gracefully`);
      
      // Зупинка моніторингу
      if (dbHealthCheckInterval) {
        clearInterval(dbHealthCheckInterval);
      }
      
      // Закриття HTTP сервера
      server.close(async () => {
        logger.info('HTTP server closed');
        try {
          // Відключення від бази даних
          await disconnectDatabase();
          logger.info('Database disconnected');
        } catch (error) {
          logger.error('Error during database disconnection:', error);
        }
        process.exit(0);
      });
      
      // Форсоване завершення через 10 секунд якщо graceful shutdown не спрацював
      setTimeout(() => {
        logger.error('Forced shutdown after timeout');
        process.exit(1);
      }, 10000);
    };
    
    // Обробка сигналів завершення
    process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
    process.on('SIGINT', () => gracefulShutdown('SIGINT'));
    
  } catch (error) {
    logger.error('Failed to start server:', error);
    process.exit(1);
  }
}
```

**Пояснення:** Сервер коректно завершує роботу: закриває HTTP з'єднання, відключається від бази даних та дає час для завершення поточних запитів перед виходом з процесу.

## Захист від зловмисних запитів

### Rate Limiting для захисту API

Реалізовано обмеження частоти запитів для захисту від DDoS та брутфорс атак. Це було важливо для забезпечення безпеки системи.

```typescript
import rateLimit from 'express-rate-limit';

// Загальне обмеження: 100 запитів на 15 хвилин з одного IP

  max: Number(process.env.RATE_LIMIT_MAX_REQUESTS) || 100, // 100 запитів
  message: 'Too many requests from this IP, please try again later',

// Строгіше обмеження для auth endpoints: 5 спроб входу на 15 хвилин
export const authRateLimiter = rateLimit({

  max: 5, // Тільки 5 спроб
  message: 'Too many login attempts, please try again later',
  skipSuccessfulRequests: true // Не рахувати успішні запити
});
```

Реалізовано форму входу з інтеграцією з Redux та автоматичним перенаправленням. Це було важливо для забезпечення зручного користувацького досвіду.

```typescript
const LoginPage = () => {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [loading, setLoading] = useState(false);
  const navigate = useNavigate();
  const dispatch = useAppDispatch();
  
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setLoading(true);
    
    try {
      // Відправка запиту на вхід
      const response = await authService.login({ email, password });
      
      // Збереження даних користувача в Redux store
      dispatch(setUser(response.data.user));
      dispatch(setTokens({
        accessToken: response.data.accessToken,
        refreshToken: response.data.refreshToken
      }));
      
      toast.success('Успішний вхід!');
      
      // Перенаправлення залежно від ролі
      const role = response.data.user.role;
      if (role === 'ADMIN') {
        navigate('/admin/dashboard');
      } else {
        navigate('/dashboard');
      }
    } catch (error: any) {
      toast.error(error.response?.data?.error?.message || 'Помилка входу');
    } finally {
      setLoading(false);
    }
  };
  
  return (
    <form onSubmit={handleSubmit} className="glass p-8 rounded-2xl">
      <input
        type="email"
        placeholder="you@example.com"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        required
      />
      <input
        type="password"
        placeholder="Password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
        required
      />
      <button type="submit" disabled={loading}>
        {loading ? 'Вхід...' : 'Увійти'}
      </button>
    </form>
  );
};
```

**Пояснення:** Форма входу інтегрується з Redux для збереження стану аутентифікації та автоматично перенаправляє користувача на відповідну сторінку залежно від його ролі.

## Технологічний стек

**Backend:**

- Layered Architecture (Controllers → Services → Database)
- RESTful API
- Real-time communication через WebSocket
